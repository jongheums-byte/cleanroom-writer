CLEANROOM AI · AI 실전 18 [AI 실전 21] 광고 싫어서 AI로 직접 만든 화살표 퍼즐 게임 스토어 스크린샷 한 장에서 100% 풀리는 무광고 PWA 웹게임까지 — 설계 인터뷰와 DAG 검증 기록

잠시 머리를 식히려고 켠 퍼즐 게임에서, 정작 퍼즐보다 긴 30초짜리 전면 광고를 보고 나면 손에서 힘이 빠질 때가 있습니다. 최근 1억 회 이상 다운로드된 Easybrain의 Arrow Puzzle(화살표 퍼즐)은 규칙이 단순하고 화면이 깔끔해서 매력적인 게임입니다. 격자 위에 촘촘히 얽힌 꺾인 화살표 가운데 앞길이 완전히 비어 있는 것을 찾아 탭하면, 화살표가 뱀처럼 스르륵 빠져나가는 구조입니다.

물론 무료 모바일 게임이 수많은 사용자에게 서비스를 유지하려면 광고 수익 모델이 필요합니다. 구조적으로 합리적인 선택이지만, 온전히 집중해서 몇 판만 풀고 싶은 개인 사용자의 입장에서는 잦은 팝업과 배너가 사고의 흐름을 끊는 외부 간섭으로 작용합니다.

예전 같으면 광고 제거 상품을 결제하거나 그냥 앱을 지우는 것 외에 선택지가 없었습니다. 그런데 문득 이런 생각이 들었습니다. "내가 쓸 게임인데, 광고 없는 내 버전을 직접 만들어 버리면 어떨까?" 그래서 스토어 화면 스크린샷 딱 한 장을 AI 에이전트에게 건네고, 코딩을 시작했습니다.

1. 스크린샷 한 장과 6단계 설계 인터뷰

코드를 바로 짜달라고 요청하지 않았습니다. 이전 [AI 실전 13]에서 정리한 /grill-me 루틴을 꺼내, 구현 전에 설계 결정부터 하나씩 확정했습니다. 스크린샷을 본 AI가 먼저 6가지 축을 순서대로 질문했고, 각 갈림길에서 방향을 잠갔습니다.

설계 항목확정한 스펙
플랫폼 & 스택React + TypeScript + Vite + HiDPI HTML5 Canvas (PC·모바일 반응형 + 오프라인 PWA)
핵심 규칙앞쪽 직선 경로가 비어 있으면 뱀처럼 탈출 / 하트 3개 · 타이머 없음 (설정에서 무제한 힐링 모드 전환)
레벨 & 보드5×5 입문 → 22×22 대형 무한 시드 캠페인 + 9종 실루엣(하트·별·도넛 등) + 날짜 시드 데일리 챌린지
조작 & 보조마우스 휠·핀치 줌, 드래그 이동, 화면 맞춤, 격자·직선 가이드선 토글, 레벨당 무료 힌트 3회(자동 포커스)
비주얼 & 사운드기본 미니멀 잉크 + 4종 테마(다크·블루프린트·파스텔) + Web Audio API 합성 효과음 및 진동
화면 & 저장접속 즉시 플레이하는 원스크린 + 달력·레벨·통계·설정 모달 + localStorage 자동 저장

막연하게 "이거랑 비슷하게 만들어줘"라고 지시했을 때와 가장 크게 달랐던 지점은 '예외 상황'이 미리 정리되었다는 점입니다. 예를 들어 20×20 이상 촘촘한 보드에서는 손가락으로 얇은 화살표를 누르기 어렵고, 한 번 드래그하려다 잘못 탭해 하트를 잃기 쉽습니다. 이 문제를 구현 전에 짚고 넘어간 덕분에 탭-드래그 구분 임계값(8px)과 여백 보정 히트테스트가 처음부터 설계에 반영되었습니다.

2. 단순해 보이지만 가장 까다로운 난관: "절대 막히지 않는 보드"

화살표 퍼즐을 겉으로만 보면 단순히 선을 많이 그리면 될 것 같지만, 실제로 구현해 보면 가장 핵심적인 공학적 난관은 '100% 풀리는 고밀도 배치'입니다.

격자를 꺾인 화살표로 무작위 채우기만 하면 어떤 일이 벌어질까요? 20×20처럼 화살표가 수십 개 이상 얽힌 보드에서는 거의 필연적으로 순환 교착(Deadlock Cycle)이 발생합니다. 화살표 A의 앞을 B가 막고, B의 앞을 C가 막고, 다시 C의 앞을 A가 막아 서로 영원히 빠져나가지 못하는 상태입니다. 플레이어가 아무리 고민해도 해법이 존재하지 않는 '불량 레벨'이 만들어집니다.

이 문제를 해결하는 방식은 제약·바이오 품질관리(QC)에서 말하는 사후 검사 중심 관리와 공정 중 관리(IPC, In-Process Control)의 차이와 정확히 맞닿아 있습니다.

사후 검사 방식(생성 후 폐기): 보드를 무작위로 꽉 채운 뒤 풀리는지 검사하고, 안 풀리면 통째로 버리고 다시 만듭니다. 보드가 커질수록 불량률이 급격히 높아져 연산 낭비가 커집니다.

설계 기반 예방 방식(증분형 DAG 검증): 화살표를 보드에 하나 추가할 때마다 방향성 비순환 그래프(DAG, 순환 고리가 없는 방향 관계망) 조건을 실시간으로 검사합니다. 새로 놓으려는 화살표가 기존 화살표들과 순환 고리를 만들 가능성이 조금이라도 있으면 그 자리에서 배치를 거부합니다.

실제 구현에 추가한 이중 안전장치
1. 고립 셀 흡수(Tail Extension): 꺾인 화살표를 촘촘하게 배치하다 남는 1칸짜리 빈 공간은 인접한 화살표의 꼬리를 늘려 흡수하되, 늘린 칸이 자기 자신의 전방 시야를 가리거나 새 순환을 만들지 않는 경우에만 허용했습니다. 2. 독립 솔버의 최종 출하 시험(Release Testing): 생성이 끝난 모든 레벨은 별도의 위상 정렬 솔버(solvePuzzle)로 실제 탈출 시뮬레이션을 끝까지 돌려 남은 화살표가 0개인지 확인한 뒤에만 화면에 내보냅니다.
3. 품질 설계 비유가 설명하는 것과, 설명하지 못하는 것

[AI 브리핑.20]에서 다루었던 설계공간(Design Space)의 관점에서 보면, 무작위 생성 후 불량을 골라내는 대신 생성 규칙 자체에 결함 방지 제약(DAG 불변식)을 심어 넣은 것은 꽤 깔끔한 품질 설계 사례입니다. 자동 테스트(Vitest)를 돌려 확인한 결과도 명확했습니다.

검증 항목자동 테스트 결과
캠페인 레벨 1 ~ 30 전수 검증30개 전 레벨 100% 해법 존재, 셀 중복·마스크 이탈 0건
9종 실루엣 보드 (12×12 · 16×16)사각·라운드·다이아몬드·하트·별·도넛·십자·왕관·모래시계 전수 통과
데일리 챌린지 시드 결정성동일 날짜 입력 시 100% 동일한 보드 재현
대형 22×22 마스터 보드 생성 속도250ms 이내 생성 완료 및 100% 해법 검증 통과
정적 타입 및 프로덕션 빌드TypeScript 오류 0건, Vite 프로덕션 번들 및 PWA 구성 완료

다만 이 비유에는 분명한 한계도 존재합니다.

첫째, 물리적 원료와 생물학적 변동성이 개입하는 제조 공정과 달리, 소프트웨어의 그래프 구조는 수학적으로 완벽히 결정론적입니다. 알고리즘 조건만 지키면 '풀리지 않는 불량'은 확률적으로 줄어드는 수준이 아니라 논리적으로 0%가 됩니다.

둘째, '100% 풀린다'는 수학적 무결성이 곧 '재미있다'는 사용자 경험을 보장하지는 않습니다. 모든 화살표가 바깥쪽만 바라보게 배치해도 100% 풀리지만, 그런 퍼즐은 아무런 긴장감이 없습니다. 그래서 서로의 경로를 적당히 가로막으며 여러 단계(Wave)에 걸쳐 양파 껍질처럼 풀려나가는 배치에 가산점을 주었고, 탈출 시에는 화살표가 통째로 평행 이동하지 않고 기존 꺾임 꼭짓점을 따라 뱀처럼 감겨 빠져나가도록 호길이(arc-length) 보간 애니메이션과 상승 음계 효과음까지 다듬어야 비로소 '손맛'이 살아났습니다.

규격 적합성(Spec Compliance)은 출발선일 뿐, 최종 가치는 실제 사용하는 사람이 느끼는 경험에서 완성됩니다.

4. 개인 맞춤 소프트웨어(Personal Software)가 여는 일상
구분기존 무료 모바일 앱직접 만든 무광고 웹앱(PWA)
광고·결제 유도스테이지 전환·힌트·부활 시 광고 시청전면 제거 (무료 힌트 · 힐링 모드 즉시 전환)
기능 맞춤화앱이 정한 규칙과 테마만 사용4종 테마, 가이드선, 줌/팬, 단축키까지 내 입맛대로 설계
설치 및 데이터앱스토어 설치 · 트래킹 SDK 포함브라우저 즉시 실행 · 오프라인 PWA · 로컬 기기 저장
유지보수 주체개발사 업데이트에 의존불편한 점이 생기면 내가 바로 수정 가능

이번 작업을 마치고 브라우저에서 직접 몇 판을 풀어 보면서 가장 크게 체감한 변화는 기술 자체보다 태도의 변화였습니다. 예전에는 앱을 쓰다 불편한 점(광고, 눈이 피로한 배색, 너무 작은 터치 영역)이 있어도 "원래 그런가 보다" 하고 감수했습니다. 하지만 이제는 "내 기준에 맞게 직접 고쳐 쓰거나 새로 만든다"는 선택지가 현실적인 비용 안에 들어왔습니다.

거창한 상용 서비스를 만들려는 것이 아닙니다. 일상의 작은 불편을 내 손으로 걷어내고, 방해 요소 없는 나만의 깔끔한 도구를 하나씩 갖추어 가는 것 — AI 코딩 시대가 개인에게 주는 가장 실용적인 혜택이 바로 여기에 있습니다.

자주 묻는 질문

Q1. 코딩을 전혀 몰라도 이런 게임을 만들 수 있나요?

코드를 한 줄씩 직접 쓰지 않더라도, "막힌 화살표를 눌렀을 때 어떻게 반응해야 하는지", "20×20 보드에서 조작이 불편하지 않으려면 어떤 보조 기능이 필요한지" 같은 사용자 관점의 요구사항을 구체적으로 설명할 수 있다면 충분히 만들 수 있습니다.

Q2. 생성된 퍼즐이 중간에 꼬여서 못 풀게 되는 경우는 없나요?

없습니다. 이 게임의 규칙상 탈출 가능한 화살표 하나를 빼내는 행위는 다른 화살표의 길을 열어주기만 할 뿐 새로운 막힘을 만들지 않습니다. 여기에 최초 생성 단계의 DAG 사이클 차단과 출하 전 위상 정렬 검증을 이중으로 적용해 모든 레벨이 100% 풀리도록 보장합니다.

Q3. 스마트폰에서도 앱처럼 쓸 수 있나요?

네. 반응형 터치(핀치 줌·드래그 팬)와 PWA(Progressive Web App) 설정을 포함해 두었기 때문에, 정적 호스팅(Netlify 등)에 올려두면 모바일 브라우저에서 '홈 화면에 추가'해 오프라인 앱처럼 실행할 수 있습니다.

AI 실전 21 · TAKEAWAY 불편을 참으며 남이 만든 환경에 맞추던 시대에서, 내 기준의 '무광고·무결점 도구'를 직접 설계하는 시대로 넘어가고 있습니다. 완벽한 결과물은 막연한 요청이 아니라, 구현 전의 명확한 스펙 합의와 결함을 원천 차단하는 검증 구조에서 나옵니다.
