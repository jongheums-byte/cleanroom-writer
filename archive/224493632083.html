CLEANROOM AI · AI 브리핑 35 제미나이 4 카본(Carbon) 합류로 완성된 안티그래비티 '3대장' 체제 Google AI Pro 개방, /swarm 병렬 협업, 그리고 카본·네온·하이드로젠 실전 분업 기준까지

구글의 에이전트 기반 개발 환경인 안티그래비티(Google Antigravity)를 쓰고 계신 분들에게 꽤 반가운 변화가 생겼습니다.

그동안 미국 기준 월 $99.99 이상의 최상위 요금제(Google AI Ultra)나 유료 API 사용자 중심으로 열려 있던 최상위 프론티어 모델 '제미나이 4 카본(Gemini 4 Carbon)'이 2026년 11월 23일부터 Google AI Pro(미국 기준 월 $19.99) 구독자에게도 안티그래비티 내부에서 전면 개방되었습니다.

그동안 블로그에서 [특별 기고]로 가볍고 신중한 실행자 하이드로젠(Hydrogen)을, [AI 브리핑.26]에서 균형 잡힌 주력 모델 네온(Neon)을 살펴보았습니다. 이번 카본(Carbon)의 합류로, 안티그래비티의 제미나이 4 주기율표 라인업은 마침내 역할이 뚜렷한 '3대장' 분업 체제를 완성하게 되었습니다.

단순히 "더 똑똑한 모델이 하나 더 나왔다"는 소식이 아닙니다. 이번 변화의 핵심은 구글이 최상위 모델 하나에 모든 일을 몰아주는 대신, '설계·검토'와 '병렬 실행'을 구조적으로 분리하기 시작했다는 점에 있습니다.

1. 제미나이 4 카본(Carbon)은 무엇이 다른가: 안티그래비티 3대장 비교

제미나이 4 카본은 2026년 10월 28일 사이버보안 방어용 프리뷰(Fairwind Program)로 처음 모습을 드러낸 뒤, 11월 10일 유료 API(Google AI Studio·Vertex AI)를 거쳐 11월 23일 안티그래비티 Pro 티어까지 확장된 최상위 프론티어 추론·에이전트 모델입니다.

빠른 단답을 내놓는 모델이 아니라, 100만(1M) 토큰 컨텍스트 안에서 사고 토큰(Thinking Tokens)을 깊게 소모하며 장기 작업(Long-horizon)의 설계·디버깅·보안 검증을 끝까지 파고드는 성격을 가집니다. 기존에 다룬 하이드로젠·네온과 나란히 놓고 보면 3대장의 역할 분담이 한눈에 정리됩니다.

2. 안티그래비티에서 실질적으로 달라진 3가지 변화

카본의 Pro 티어 개방과 맞물려, 실제 작업 화면에서 체감되는 구조적 변화는 크게 세 가지입니다.

① 단일 프롬프트로 팀을 띄우는 /swarm (프리뷰): 기존에는 에이전트 한 명이 파일 A를 고치고, 끝나면 파일 B를 고치는 직렬 방식이었습니다. /swarm 명령을 쓰면 하나의 지시가 독립된 Git 워크트리(Worktree)에서 동시에 일하는 여러 워커와, 결과물을 반박·검증하는 검증자(Verifier) 팀으로 펼쳐집니다. 작업 공간이 격리되어 있어 파일 편집 충돌이 나지 않고, 공유 메시지 보드로 실시간 진행 상황을 지켜볼 수 있습니다. 예를 들어 /swarm "화면 UI 개편은 프론트 워커가, API 검증 로직은 백엔드 워커가 독립 워크트리에서 동시에 구현하고, 검증자 1명이 통합 테스트와 예외 케이스를 점검해 줘"처럼 역할과 산출물 경계만 한 줄로 나누어 지시하면 됩니다.

② 카본 중심의 Orchestrator 동적 분업과 구형 모델 재편: [AI 브리핑.25]에서 다룬 오케스트레이터(Orchestrator)가 한 단계 진화했습니다. 초기 구조 설계나 까다로운 원인 추적은 카본이 맡고, 합의된 계획대로 파일을 수정하고 테스트를 돌리는 반복 구간은 하이드로젠·네온으로 넘겨 처리합니다. 이에 따라 기존 Argon 일부 버전은 최신 4세대 3대장 라인업으로 순차 재편되고 있습니다.

③ Google AI Pro(미국 기준 월 $19.99) 개방과 통합 할당량(Quota) 관리: Ultra 구독자만 만져볼 수 있던 최상위 추론 모델을 Pro 구독자도 안티그래비티 안에서 직접 쓸 수 있게 되면서 진입 장벽이 크게 낮아졌습니다. 다만 카본은 사고 토큰을 깊게 쓰는 특성상, 모든 단순 질문에 카본을 고정해 두면 할당량이 빠르게 소진될 수 있습니다.

3. 왜 '제일 센 모델 하나'가 아니라 '3대장 분업'으로 갈까?

막상 써 보면 자연스럽게 드는 의문이 있습니다. "카본이 제일 똑똑하다면, 그냥 처음부터 끝까지 카본 하나만 쓰면 되는 거 아닌가?"

실제 프로젝트에 AI 에이전트를 붙여 보면 답이 금방 나옵니다. 단순한 오타 수정이나 정형화된 파일 5개 편집에까지 매번 최상위 추론 모델이 수십 초씩 깊게 고민하면 작업 속도는 답답해지고 사용량(Quota)만 순식간에 바닥납니다. 반대로 여러 모듈이 얽힌 설계나 원인이 안 잡히는 버그를 가벼운 모델에만 맡기면, 겉보기엔 빠르게 고치지만 엉뚱한 곳을 망가뜨려 오히려 시간이 두 배로 듭니다.

실제 개발·실무 팀에서도 시니어 아키텍트가 전체 구조와 핵심 리스크를 잡으면, 정해진 명세에 따른 구현과 반복 수정은 여러 팀원이 병렬로 나누어 처리합니다. 안티그래비티의 Orchestrator와 /swarm은 바로 이 팀 협업 구조를 모델 단위 분업으로 옮겨 놓은 것입니다.

그렇다면 현업 화면에서 "네온으로 충분한 작업"과 "카본으로 올려야 하는 작업"의 경계는 무엇으로 가를 수 있을까요? 감으로 고르기보다, 작업 도중 나타나는 세 가지 구체적 신호를 기준으로 삼으면 판단이 훨씬 명확해집니다.

구분 (판단 신호)네온(Neon)으로 충분한 사례카본(Carbon)으로 올려야 하는 신호
① 변경 영향 범위 (다중 파일 의존성)단일 화면 UI 수정, 개별 함수 개선, 기존 API 응답에 필드 1개 추가처럼 영향 범위가 1~2개 파일에 닫힌 작업인증 상태·공용 데이터 스키마·핵심 유틸처럼 한 곳을 고치면 5~10개 이상 파일의 호출 규약이 연쇄적으로 흔들리는 작업
② 오류 해결 패턴 (회귀 실패 반복)에러 로그가 명확하고 1~2번 수정으로 테스트가 바로 통과하는 일반 버그A를 고치면 B가 깨지고, B를 되돌리면 A가 다시 터지는 회귀 실패가 2회 이상 반복되는 순간 (표면 패치 중단 → 근본 원인 역추적 필요)
③ 실패 시 복구 비용 (보안·권한 경계)내부 대시보드 스타일링, 사내 문서 요약, 개인 프로토타입처럼 틀려도 즉시 되돌릴 수 있는 작업로그인·토큰 검증·권한 분기(RBAC), 외부 웹훅, 결제·데이터 삭제처럼 예외 케이스 하나가 보안 사고나 데이터 손실로 이어지는 구간

실제로 현업에서 가장 체감이 큰 것은 두 번째인 '2회 반복(2-Strike) 신호'입니다. 네온으로 빠르게 버그를 잡다가 같은 테스트가 두 번 이상 엇갈리면, 프롬프트를 더 길게 늘려 쓰기보다 즉시 카본으로 전환해 비동기 타이밍이나 숨은 상태 충돌을 바닥부터 짚어내게 하는 편이 전체 시간과 할당량을 모두 아끼는 지름길입니다.

마찬가지로 세 번째인 보안·권한 경계는 카본이 본래 사이버보안 취약점 점검(Fairwind Program)으로 먼저 검증된 영역인 만큼, 이 구간만큼은 할당량을 아끼지 않고 카본에게 엣지 케이스 검토를 맡기는 것이 안전합니다.

다만 한 가지는 분명히 선을 그어 두어야 합니다. /swarm 안에서 카본이 아무리 꼼꼼하게 설계하고 검증자 역할을 돌리더라도, 최종 결과물이 내 의도와 실제 사용 환경에 맞는지 확인하고 확정하는 최종 결정권자는 여전히 사용자 본인입니다. 모델 분업은 작업 속도와 완성도를 크게 끌어올려 주지만, 확인 과정을 완전히 대신해 주지는 않습니다.

실전에서 안티그래비티 3대장을 고르는 4가지 기준
1. 구조 설계·난제 디버깅·보안 경계 → 카본(Carbon): 다중 파일 의존성 변경, 2회 이상 반복되는 회귀 버그, 권한·인증·결제 로직 정밀 검토에 투입한다. 2. 일상 개발·문서 작성·일반 분석 → 네온(Neon): 영향 범위가 명확한 평소 주력 작업에 두고, 작업 난이도에 맞춰 추론 기어만 조절해 할당량을 아낀다. 3. 단순 반복·병렬 작업·빠른 수정 → 하이드로젠(Hydrogen): 명확한 지시가 떨어진 대량 정리나 /swarm 하위 워커 실행용으로 활용한다. 4. 헷갈릴 때는 Orchestrator 모드 활용: 매번 수동으로 모델을 바꾸기 번거롭다면, 설계(카본)와 실행(네온·하이드로젠)을 자동으로 나눠 주는 오케스트레이터를 기본값으로 둔다.
마치며

모델 이름 뒤에 붙는 숫자와 원소 기호가 늘어날수록 "가장 비싸고 최신인 모델 하나만 고르면 끝"이라고 생각하기 쉽습니다. 하지만 제미나이 4 카본의 안티그래비티 합류가 보여주는 방향은 조금 다릅니다.

가장 강한 모델을 '아무 데나' 쓰는 것이 아니라, 가장 중요한 설계와 검증 지점에 정확히 배치하고 나머지는 빠르고 가벼운 실행자에게 나누어 주는 것. 안티그래비티 3대장 체제가 완성된 지금, 도구를 잘 쓰는 기준은 모델 스펙을 외우는 데서 나오지 않고 내 작업 단계마다 어떤 모델에게 어떤 역할을 맡길지 나누는 감각에서 갈리게 됩니다.

자주 묻는 질문

Q1. 무료 사용자도 안티그래비티에서 제미나이 4 카본(Carbon)을 쓸 수 있나요?

현재 안티그래비티 내 카본 접근은 기존 Ultra 티어에서 Google AI Pro(미국 기준 월 $19.99) 유료 구독자까지 확대된 상태이며, API 역시 유료 티어(Google AI Studio·Vertex AI)를 통해 제공됩니다.

Q2. 평소에 쓰던 네온(Neon) 대신 무조건 카본(Carbon)으로만 작업하��� 게 더 좋나요?

권장하지 않습니다. 카본은 깊은 사고 토큰을 사용하기 때문에 단순 텍스트 수정이나 가벼운 작업에 쓰면 응답 속도가 느려지고 할당량(Quota)만 빨리 소모됩니다. 일상 작업은 네온으로 유지하고, 복잡한 설계·디버깅이나 /swarm 총괄 지휘가 필요할 때 카본을 꺼내 쓰는 것이 효율적입니다.

AI 브리핑 35 · TAKEAWAY 카본(Carbon)의 합류로 안티그래비티는 '단일 모델'을 넘어 '설계(카본) × 균형(네온) × 속도(하이드로젠)' 3대장 분업 체제로 진화했습니다. Google AI Pro 구독자라면 모든 작업에 카본을 고정하기보다, 복잡한 초기 설계와 까다로운 검토 구간에만 카본을 투입하고 실행은 네온·하이드로젠과 /swarm에 맡기는 전략이 속도와 할당량을 모두 챙기는 가장 현실적인 사용법입니다.
