지난 [AI 브리핑 17]에서 우리는 "에이전트에게 스킬(Skill)을 많이 쥐여줄수록 오히려 판단이 흐려지고 비용과 지연이 커질 수 있다"는 점을 살펴보았습니다. 이론을 짚고 넘어갔으니, 이번에는 실제로 '덜어내는 설계'를 실무 도구로 만들어 볼 차례입니다.

회의가 끝나고 나면 메모장이나 메신저에 두서없이 적어둔 문장들이 남습니다. 누군가의 할 일, 이미 확정된 결정사항, 아직 확인이 더 필요한 안건이 한데 뒤섞여 있습니다. 이 메모를 정리하자고 매번 AI 에이전트를 열고, 회의록 분석 스킬을 불러오고, 긴 프롬프트를 입력하는 과정이 과연 가장 효율적인 방법일까요?

오늘은 AI에게 스킬을 더 붙이는 대신, 딱 한 가지 일만 1초 만에 처리하는 '단일 목적 웹 도구'를 직접 만들어 본 과정을 공유합니다.

1. 왜 '범용 AI 스킬'이 아니라 '단일 목적 HTML 도구'인가?

제약·바이오 품질관리(QC) 실험실에서는 시료의 무게 하나를 잴 때 수십 가지 기능이 들어 있는 복합 분석 장비를 켜지 않습니다. 예열과 교정 절차가 복잡한 범용 장비 대신, 전원을 켜면 무게만 정확히 재는 단일 목적 저울을 사용합니다.

업무 자동화도 마찬가지입니다. 모든 문제를 AI 추론(LLM 호출)으로 풀 필요는 없습니다. 메모에서 '할 일', '결정사항', '미결 안건'을 분리하고 @담당자와 기한을 뽑아내는 작업은 상당 부분 규칙 기반(Deterministic)으로 즉시 처리 가능한 영역입니다.

이번에 만든 메모·회의록 액션아이템 추출기는 다음 세 가지 원칙으로 설계했습니다.

1. 단일 목적 (Single Purpose): 오직 '두서없는 텍스트에서 액션아이템·결정사항·미결 안건 분리' 한 가지 기능만 수행합니다. 2. 외부 의존성 제로 (Zero Dependency): 외부 API 키, 서버, 무거운 npm 패키지 없이 단일 index.html 파일 하나로 브라우저에서 즉시 실행됩니다. 3. 0ms 실시간 피드백: 문장을 붙여넣는 순간 지연 시간 없이 바로 분류 결과가 화면에 반영됩니다.

2. 직접 만든 도구 구조 살펴보기

도구의 구성은 단순합니다. 왼쪽 입력창에 회의 중 급하게 적은 메모를 붙여넣으면, 오른쪽 화면이 이를 세 갈래로 나누어 보여줍니다.

📌 액션아이템: ~하기, ~할 것, ~확인 후, @담당자 패턴이 포함된 줄을 추출하고, @이름과 날짜·요일(내일, 다음주 수요일, 11/18 등)을 인식해 배지로 달아줍니다. 완료 체크박스도 함께 생성됩니다.

✅ 확정된 결정사항: 확정, 결정, 합의, 채택 등의 키워드가 포함된 문장을 따로 모읍니다.

❓ 미결·추가 확인 필요: 물음표(?)나 미정, 재확인, 추후 확인, 보류가 포함된 항목을 분리해 회의 후 놓치기 쉬운 쟁점을 한눈에 띄워줍니다.

3. 실전 사용 흐름: 붙여넣기부터 Markdown 복사까지

실제로 주간 점검 회의 메���를 넣었을 때의 동작은 다음과 같습니다.

왼쪽 입력창에 날짜, 논의 내용, @담당자, 기한이 섞인 메모를 그대로 붙여넣습니다.

상단 요약 카드에 추출된 액션아이템 4건, 확정된 결정사항 2건, 미결·확인 필요 2건처럼 숫자가 즉시 집계됩니다.

오른쪽 목록에서 담당자와 기한 배지가 올바르게 붙었는지 확인한 뒤, 우측 상단의 [정리 결과 복사 (Markdown)] 버튼을 누릅니다.

- [ ] @김대리 다음주 수요일까지 시험성적서 양식 초안 공유하기 (담당: 김대리 / 기한: 다음주 수요일까지) 형태의 깔끔한 체크리스트가 클립보드에 복사되어 노션, 슬랙, 메일에 바로 붙여넣을 수 있습니다.

4. AI는 '만능 집행자'가 아니라 '도구 제작자'로 쓸 때 가장 가볍다

이 작업에서 AI가 한 역할은 매번 회의록을 대신 읽어주는 것이 아니었습니다.

반복되는 분류 규칙을 정리해, 누구나 브라우저만 열면 1초 만에 쓸 수 있는 작은 HTML 도구 하나를 설계하고 구현해 준 것입니다.

한 번 이렇게 단일 목적 도구를 만들어 두면 이후에는 토큰 비용도, 네트워크 대기도, 프롬프트를 다시 다듬는 수고도 들지 않습니다.
