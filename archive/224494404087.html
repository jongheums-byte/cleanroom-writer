2026년 11월 27일 기준, AI 도구(ChatGPT·Claude·Google AI Pro 등)와 OTT·생활 멤버십 구독이 늘어나면서 매달 빠져나가는 고정비를 한눈에 점검하려는 수요가 커지고 있습니다.

이번 [AI 실전 23]에서는 회원가입도, 카드사 연동도, 유료 API 키도 없이 내 PC와 스마트폰 브라우저에서만 돌아가는 단일 HTML 구독료 정리기를 바이브 코딩으로 직접 만들고 검증해 봅니다.

“구독 관리 앱을 깔려니 은행·카드사 로그인을 요구해서 찝찝하고, 그렇다고 엑셀에 적어두자니 매번 열어서 다음 결제일과 D-day를 계산하기가 번거롭습니다. 내 데이터는 밖으로 안 내보내면서 캘린더 알림까지 챙길 수 있는 방법은 없을까요?”

단일 HTML 파일과 브라우저 로컬 저장소(localStorage), 그리고 표준 캘린더(.ics) 내보내기를 조합하면 외부 서버 전송 0건으로도 충분히 실용적인 개인 구독 관리 도구를 만들 수 있습니다.

1. 왜 카드 연동 앱 대신 '단일 HTML 파일'인가

구독 서비스 지출을 관리하는 방법은 크게 세 가지로 나뉩니다. 카드사·은행을 연동하는 상용 가계부 앱, 직접 수식을 짜는 엑셀·구글 시트, 그리고 내 PC에 파일 하나로 두는 단일 HTML 웹앱입니다.

상용 앱은 자동 수집이 편하지만 금융 인증서를 넘겨야 하고 무료 체험 해지 알림이나 광고가 따라붙기 쉽습니다. 반면 엑셀은 매달 결제일이 지난 뒤 다음 달 D-day를 자동으로 밀어주려면 날짜 함수가 꽤 복잡해집니다.

특히 AI 서비스는 달러(USD) 결제가 많고 무료 체험 기간이 짧은 편이라, 내가 직접 환율을 바꿔보며 월간 총액을 가늠하고 캘린더에 3일 전 알림을 꽂아두는 단순한 도구가 훨씬 실용적입니다.

2. 바이브 코딩 전 반드시 잠가야 할 3가지 설계 규칙

비개발자가 AI에게 "구독료 정리 웹앱 하나 만들어줘"라고 막연히 부탁하면, 겉보기에만 그럴듯하고 실제로 쓰면 어긋나는 세 가지 버그가 자주 발생합니다.

코드 생성을 시키기 전에 아래 세 가지 규칙을 프롬프트에 명시해 두어야 시행착오를 줄일 수 있습니다.

1. 첫째, 31일·2월 말일 결제일 보정 규칙을 명시합니다.

매월 31일에 결제되는 서비스를 다음 해 2월로 넘길 때 단순 덧셈(month + 1)을 쓰면 날짜가 3월 3일로 밀려버리는 문제가 생깁니다. 해당 월의 마지막 날(daysInMonth)과 비교해 Math.min(설정일, 말일)로 잘라주는 클램핑(Clamping) 규칙을 먼저 고정해야 합니다.

2. 둘째, 외부 폰트·라이브러리(CDN) 없이 완전 오프라인으로 동작하게 묶습니다.

외부 차트 라이브러리나 웹폰트 링크를 넣으면 사내 폐쇄망이나 오프라인 환경에서 화면이 깨질 수 있습니다. index.html 한 파일 안에 CSS와 바닐라 자바스크립트를 모두 담아 외부 네트워크 요청이 0건이 되도록 제한합니다.

3. 셋째, localStorage 휘발성을 보완하는 JSON 백업과 .ics 내보내기를 넣습니다.

브라우저 저장소는 인터넷 사용 기록을 지우거나 PC를 바꾸면 사라집니다. 언제든 내 구독 목록을 .json 파일로 내려받아 다른 브라우저로 옮길 수 있어야 하며, 캘린더 앱(구글·애플·네이버 캘린더)이 표준으로 읽는 .ics 포맷(TRIGGER:-P3D)을 함께 생성하도록 설계합니다.

3. 직접 만들고 돌려본 실측 검증 결과

위 세 가지 규칙을 바탕으로 실제 단일 파일(blog_drafts/subscription_tracker_lab/index.html)을 작성한 뒤, 헤드리스 브라우저(Playwright · Chromium 1280×800)로 기능과 엣지케이스를 직접 검증했습니다.

실측 검증 결과 요약 (2026년 11월 27일 Playwright Chromium · file:/// 로컬 파일 실행 기준)
• 외부 네트워크 요청 0건 확인: Chromium 헤드리스 환경에서 file:/// 경로로 파일을 연 뒤 전체 동작 중 외부 서버로 나가는 요청을 감시한 결과 0건으로 확인됨. (단, 브라우저 종류나 보안 정책에 따라 file:// 오리진의 localStorage 유지 및 파일 다운로드 동작에 차이가 생길 수 있어 JSON 백업 병행 또는 간단 로컬 서버 활용을 권장함.) • 합산 및 새로고침 보존 실측: 테스트 구독 5건(Google AI Pro 월 $19.99·31일, ChatGPT Plus 월 $20.00·15일, Netflix 월 17,000원·5일, 쿠팡 와우 월 7,890원·10일, 클라우드 백업 연 120,000원·12월 20일)을 환율 1 USD &#x3D; 1,400원 기준으로 입력하자 월간 환산 총지출 90,876원 (외화 $39.99 / 월), 연간 예상 1,090,512원이 오차 없이 산출되었고, 페이지 새로고침(reload) 후에도 5건이 그대로 유지됨. • 말일 보정·윤년·연간 구독 롤오버 실측: 매월 31일 결제(Google AI Pro)는 2026-11-01 기준 2026-11-30 (D-3), 2027-02-01 기준 2027-02-28, 윤년인 2028-02-01 기준 2028-02-29로 보정됨. 연간 구독(12월 20일)은 결제일 경과 후(2026-12-21 기준) 다음 해 2027-12-20으로 정상 이월되었고, 연간 2월 29일 설정도 평년(2027-01-01 기준) 2027-02-28로 보정됨. • 표준 .ics 알림 생성 및 XSS 차단 확인: 내보내기 실행 시 BEGIN:VCALENDAR~END:VCALENDAR 내 5건의 VEVENT와 결제 3일 전 알림(TRIGGER:-P3D) 블록이 정상 생성됨. 특히 연간 구독(s5, 12월 20일) 기준 종일 일정 DTSTART;VALUE&#x3D;DATE:20261220, 배타적 종료일 DTEND;VALUE&#x3D;DATE:20261221, 고정 UID:s5@cleanroom-sub-local, TRIGGER:-P3D가 정확히 생성됨. 서비스명·메모란에 <script>alert(1)</script>·<img src&#x3D;x onerror&#x3D;alert(2)>를 입력해도 알림창 실행이 0건으로 차단되고 일반 문자열로 안전하게 출력됨.

실제 테스트 과정에서 하나 더 확인된 실무 팁은, innerHTML 대신 textContent로 화면을 그리도록 강제해야 메모란에 특수문자(<, >)나 이상한 코드가 섞여 들어와도 브라우저 화면이 망가지지 않는다는 점입니다.

4. 주말에 바로 따라 만드는 2단계 프롬프트

아래 두 개의 프롬프트를 ChatGPT, Claude, Gemini 또는 Antigravity 채팅창에 순서대로 붙여 넣으면, 코딩 지식이 없어도 위와 동일한 구조의 단일 HTML 구독 정리기를 직접 만들고 검증할 수 있습니다.

프롬프트 ① 구조와 규칙을 먼저 잠그는 제작 요청 (독자 참고 템플릿)
외부 CDN, 외부 폰트, 서버, API 호출이 전혀 없는 단일 index.html 파일 하나로 동작하는 '내 AI·OTT 구독료 정리기' 웹앱을 만들어 줘. [필수 기능과 규칙] 1. 입력 항목: 서비스명, 분류(AI/OTT/업무/생활), 주기(월간/연간), 통화(KRW/USD), 금액, 결제일(1~31일), 연간 결제월(1~12월 — 연간 구독은 지정한 월·일을 조합해 기준일 확정), 메모(무료체험 종료일 등). 2. 계산 규칙: 사용자가 입력한 USD 환율(기본 1,400원)을 적용해 월간 환산 총지출(연간 구독은 ÷12)과 연간 총지출을 상단 카드에 표시할 것. 3. 말일·연도 롤오버 규칙: 결제일이 31일인 월간 구독은 30일인 달(4·6·9·11월)은 30일, 2월은 28일(윤년 29일)로 자동 보정하고, 연간 구독은 지정한 결제월·결제일이 올해 이미 지났다면 다음 해 같은 월·일(말일 보정 포함)로 다음 결제일과 D-day를 계산할 것. 4. 저장 및 내보내기: 브라우저 localStorage 자동 저장, JSON 백업/복원 버튼, 그리고 결제일 3일 전 알림(TRIGGER:-P3D)이 포함된 표준 .ics 캘린더 파일 내보내기 버튼을 넣을 것. 5. 보안 규칙: 사용자 입력값을 화면에 그릴 때 innerHTML 대신 textContent를 사용해 XSS를 원천 차단할 것.
프롬프트 ② 완성된 HTML의 계산·보안 구멍을 스스로 점검시키는 검증 요청 (독자 참고 템플릿)
방금 만든 index.html 코드를 검토해서 아래 4가지 엣지케이스에 문제가 없는지 확인하고, 문제가 있으면 수정해 줘. 1. 2026-11-01, 2027-02-01, 2028-02-01 기준으로 결제일 31일 항목이 각각 30일, 28일, 29일로 정확히 계산되는가? 2. .ics 파일의 종일 일정(DTSTART;VALUE&#x3D;DATE)에서 DTEND가 시작일 다음 날로 올바르게 설정되고, 쉼표(,)·세미콜론(;)·줄바꿈이 이스케이프되는가? 3. 외부 스크립트나 폰트 URL(https://...)이 코드 안에 단 한 줄도 섞여 있지 않은가? 4. JSON 복원 시 잘못된 형식의 파일을 넣어도 화면이 멈추지 않고 안내 메시지를 띄우는가?
마치며

화려한 디자인을 주문하기 전에 날짜 계산 규칙과 데이터 보관 방식부터 몇 줄로 잠가두면, 주말에 만든 작은 HTML 파일 하나가 어떤 유료 구독 앱보다 깔끔하고 오래 쓰는 개인 도구가 됩니다.

이번 주말에는 평소 무심코 자동 결제되던 AI 도구와 OTT 구독 내역을 5분만 정리해 보고, 내 PC 브라우저에만 보관되는 나만의 구독 캘린더를 한 번 띄워 보시길 권합니다.

자주 묻는 질문

Q1. 이 HTML 파일은 스마트폰에서도 열어서 쓸 수 있나요?

네, 단일 HTML 파일이므로 이메일이나 메신저로 내 스마트폰에 옮겨 브라우저로 열면 바로 사용할 수 있습니다. 다만 localStorage는 기기와 브라우저별로 따로 저장되므로, PC와 스마트폰 사이에서 목록을 옮길 때는 JSON 백업 및 JSON 복원 버튼을 활용해야 합니다.

Q2. 결제일이 다가오면 브라우저가 알아서 팝업 알림을 띄워주나요?

일반 HTML 파일을 열어두지 않은 상태에서는 브라우저가 자동으로 푸시 알림을 보낼 수 없습니다. 대신 이 도구에서 캘린더 알림(.ics) 내보내기 버튼을 눌러 내려받은 파일을 구글 캘린더, 애플 캘린더, ��는 네��버 캘린더에 한 번만 가져오면, 결제 3일 전(-P3D) 알림을 휴대폰으로 정확하게 받을 수 있습니다. 참고로 구독 금액이나 결제일이 바뀐 뒤 .ics 파일을 다시 가져올 때는 캘린더 앱에 따라 기존 일정이 중복 생성될 수 있으므로, 기존 일정을 정리하거나 '구독 알림' 전용 보조 캘린더를 따로 만들어 덮어쓰기·삭제가 쉽도록 관리하는 편이 깔끔합니다.

Q3. 브라우저 방문 기록이나 캐시를 지우면 입력한 구독 목록도 날아가나요?

브라우저 설정에서 '사이트 데이터 및 쿠키'까지 함께 삭제하면 localStorage 데이터도 지워집니다. 또한 file:/// 로컬 파일 경로로 열 경우 브라우저 종류나 보안 설정에 따라 localStorage 유지·다운로드 동작이 달라질 수 있으므로, 중요한 목록을 수정한 날에는 JSON 백업 버튼을 눌러 파일 하나를 남겨두거나 가벼운 로컬 서버 환경에서 여시면 안전합니다.
