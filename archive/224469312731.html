CLEANROOM WRITER AI 실전 04 "좀 더 깔끔하게 해줘"라는 말 대신 도면을 건네다 — 피그마(Figma) 규격으로 나만의 사이트 리디자인하기 기능 코드(app.js)는 한 줄도 건드리지 않고, 상자 중첩 해체와 3단계 시각적 위계로 'AI 티 나는 화면'을 벗어나는 법 CLEANROOM AI TECH · FIGMA UI REFACTORING

지난 [AI 실전 03] 편에서는 깃허브 오픈소스(NomaDamas/k-skill)에서 항공권, 최저가 주유소, 공영주차장, 로또 당첨 번호 조회 로직을 추출해 내 사이트의 4개 슬롯에 조립해 넣었습니다.

실시간 데이터도 잘 불러오고 드롭다운으로 스킬도 즉시 교체되니 기능상으로는 부족함이 없습니다. 하지만 완성된 화면을 가만히 들여다보면, 많은 분이 공통적으로 느끼는 아쉬움이 하나 남습니다. 바로 "기능은 잘 돌아가는데, 어딘가 AI가 처음 만들어 준 특유의 딱딱하고 답답한 인상이 난다"는 점입니다.

이번 4편에서는 지난번에 만든 개인 조회 사이트의 데이터 통신 코드는 단 한 줄도 건드리지 않은 채, 디자인 도구인 피그마(Figma)의 설계 규격을 활용해 화면을 매거진·포털 위젯 스타일로 리디자인하는 공정을 다룹니다.

왜 AI에게 "더 예쁘게 바꿔줘"라고 말할수록 화면이 산으로 갈까?

AI가 처음 생성한 웹 화면을 고치려 할 때 우리가 흔히 쓰는 방식은 채팅창에 추상적인 형용사를 던지는 것입니다. "너무 개발자 도구 같아, 좀 더 깔끔하고 세련되게 바꿔줘", "여백을 좀 넓히고 요즘 앱처럼 만들어 줘"라고 지시하는 식입니다.

하지만 이런 모호한 지시를 반복할수록 AI는 배경색을 갑자기 어둡게 바꾸거나, 멀쩡히 작동하던 버튼의 위치를 옮기거나, 불필요한 그라데이션 장식을 덧칠하곤 합니다.

제조나 품질 관리 현장에서 작업자에게 "이번에는 좀 더 정밀하게 가공해 주세요"라고 구두로만 지시하면 작업자마다 결과물이 제각각으로 나오는 것과 같습니다. 일관된 품질을 얻으려면 형용사가 아니라, 허용 오차와 치수가 명시된 '도면(Drawing)'과 '수치 규격(Specification)'을 건네야 합니다.

웹 디자인에서 이 도면 역할을 하는 도구가 바로 피그마(Figma)입니다. 말로만 수십 번 재작업을 지시하는 대신, 피그마 도면 위에서 기존 화면이 왜 답답해 보이는지 원인을 진단하고 글자 크기·여백·구분선의 치수를 확정해 AI에게 전달하면 단 한 번의 수정으로 정확한 화면을 얻을 수 있습니다.

1단계 진단: AI가 만든 기본 화면은 왜 한눈에 안 들어올까?

먼저 03편에서 완성했던 기본 화면 카드를 피그마 캔버스 위로 가져와 구조를 분해해 보았습니다. AI가 기본값으로 짜준 화면이 답답해 보이는 이유는 크게 두 가지 구조적 문제 때문이었습니다.

1. 상자 안의 상자 중첩 (Box-in-Box 현상) AI는 정보를 구분할 때 무조건 '회색 배경 상자(#F8FAFC)'와 '1픽셀 실선 테두리(#E2E8F0)'를 두르는 습성이 있습니다. 그러다 보니 커다란 슬롯 카드 상자 안에 상단 헤더 상자가 있고, 그 아래 보조 지표 상자 3개가 들어 있고, 그 아래 다시 목록 상자 3개가 겹쳐 있는 '6중 상자 중첩' 구조가 만들어졌습니다. 테두리 선이 너무 많아 정작 안의 글자보다 상자 윤곽선이 눈을 피로하게 만듭니다. 2. 시각적 위계(Visual Hierarchy)의 부재 시각적 위계(Visual Hierarchy, 화면 안에서 가장 중요한 정보부터 부수적인 정보까지 시선이 머무는 순서를 글자 크기와 명암 차이로 설계하는 원칙)가 평면적이었습니다. 사용자가 이 카드를 열었을 때 1초 만에 확인하고 싶은 것은 "도쿄행 최저가가 184,200원"이라는 결론인데, 상단의 SLOT #01 배지나 하단의 영문 API 호출 주소(GET /api/k-skill/...)가 본문 수치와 비슷한 채도와 비중으로 시선을 빼앗고 있었습니다.

2단계 처방: 피그마 도면에서 확정한 3가지 디자인 토큰(Design Tokens)

문제를 정확히 진단했으니, 이제 장식을 더하는 대신 불필요한 선을 덜어내는 방향으로 피그마 설계 규격(디자인 토큰, Design Tokens — 여백, 글자 크기, 색상, 모서리 곡률 등 화면 스타일을 결정하는 표준화된 수치 값)을 정의합니다.

규칙 1: 3단계 시각적 위계(3-Tier Hierarchy) 수립

카드 안의 모든 정보를 중요도에 따라 3개 층위로 엄격히 나눕니다.

• 1순위 (핵심 결론 수치): 항공권 최저가(₩184,200), 주유소 최저가(1,629원/L)처럼 가장 먼저 봐야 할 숫자는 상단 4열 요약 바(KPI Strip)와 38~40px 대형 타이포그래피(자간 -0.04em)로 대폭 키웁니다. • 2순위 (비교 목록 및 보조 지표): 항공사별 시간표나 주유소 순위는 본문 제목 14px, 부가 설명 12px로 차이를 두어 시선이 자연스럽게 위에서 아래로 흐르게 합니다. • 3순위 (기술 메타데이터): 카드 맨 아래의 API 호출 경로와 응답 속도는 저채도로 낮추어 본문 데이터의 가독성을 방해하지 않도록 통제합니다.

규칙 2: 상자 해체(De-boxing)와 도메인 컬러 구분

카드 내부에 겹겹이 쳐져 있던 회색 테두리 상자들을 모두 제거합니다. 대신 상단에는 다크 네이비 히어로 배너와 카드별 5픽셀 도메인 컬러 스트라이프(항공 블루·주유 에메랄드·주차 퍼플·로또 오렌지)로 영역을 직관적으로 구분하고, 내부 목록은 얇은 가로 구분선(1px solid #F1F5F9)만으로 행을 나눕니다. 상자 테두리만 걷어내도 화면의 공기감이 즉시 달라집니다.

규칙 3: 고정폭 숫자(tabular-nums) 정렬

가격이나 거리, 시간을 세로로 나열할 때 숫자 1과 8의 가로 폭이 다르면 오른쪽 끝자리가 미묘하게 어긋나 보입니다. 모든 숫자에 고정폭 숫자 규격(font-variant-numeric: tabular-nums, 모든 숫자의 가로 폭을 동일하게 맞춰 표에서 자릿수가 반듯하게 정렬되도록 하는 타이포그래피 설정)을 적용해 표의 정밀도를 높입니다.

3단계 이식: 기능 코드는 건드리지 않고 스타일(style.css)만 교체하기

여기서 지난 03편의 설계가 빛을 발합니다.

03편에서 우리는 데이터를 불러오고 가공하는 엔진(app.js)과 화면의 외관을 담당하는 스타일시트(style.css)를 분리해 두었습니다. 소프트웨어 공학에서는 이를 '관심사 분리(Separation of Concerns, 프로그램의 내부 동작 로직과 외부 화면 표현을 서로 독립된 파일로 나누어 한쪽을 수정해도 다른 쪽에 오류가 생기지 않게 하는 설계 원칙)'라고 부릅니다.

따라서 리디자인을 적용할 때도 AI에게 아래처럼 명확한 범위 제한과 수치 규격을 함께 전달합니다.

실무 리디자인 지시 프롬프트 예시: "app.js의 데이터 조회 로직과 netlify.toml 프록시 설정은 단 한 줄도 수정하지 말고 그대로 유지해 줘. 오직 UI 레이어(style.css)만 수정해서 피그마에서 정의한 에디토리얼 위젯 규격(Style A)을 적용해 줘. 1. 상단 헤더는 다크 네이비(#090D16) 히어로 배너와 4열 핵심 결론 요약 바(KPI Strip)로 구성할 것. 2. 각 슬롯 카드는 모서리 곡률 24px과 상단 5px 도메인 컬러 스트라이프를 적용하고, 내부의 중첩된 회색 박스 테두리를 모두 제거해 1px 헤어라인 구분선으로 대체할 것. 3. 1순위 대표 숫자는 38px Black(-0.04em) 및 컬러 하이라이트 배너로 강조해 3단계 시각적 위계를 적용할 것."

[결과 비교] 리디자인 전(03편 Before) vs 리디자인 후(04편 After)

실제로 동일한 4대 생활 정보 데이터 위에서 스타일 규격만 교체한 전후 결과를 비교해 보겠습니다.

1. 리디자인 전 (03편 기본 박스형 화면)

각 카드 상단의 회색 헤더 바, 굵은 SLOT #01 배지, 3개의 보조 지표 상자, 3개의 목록 상자가 촘촘하게 박혀 있어 전형적인 '사내 관리자 페이지' 같은 인상을 줍니다.

2. 리디자인 후 (04편 피그마 에디토리얼 위젯 화면)

상단의 다크 네이비 히어로 배너와 4열 요약 타일(KPI Strip)이 중심을 잡아주고, 카드 내부의 불필요한 상자 테두리가 사라지면서 접속하자마자 ₩184,200(도쿄 최저가), 1,629원/L(역삼 최저가 주유소), 다크 스튜디오 로또 당첨볼이 1초 만에 시선에 들어옵니다.

내부 코드는 전혀 건드리지 않았기 때문에 노선 변경, 주유소 권역 변경, 로또 회차 조회, 그리고 [스킬 모듈 교체] 드롭다운 기능은 단 하나의 오류 없이 기존 그대로 작동합니다.

좋은 디자인은 '장식'이 아니라 '위계의 통제'에서 나온다

비전공자가 AI와 함께 웹 서비스를 만들 때 가장 빠지기 쉬운 함정은, 화면이 허전해 보인다는 이유로 색상과 테두리 상자를 계속 추가하는 것입니다. 하지만 화면에 선과 색이 늘어날수록 정작 내가 보려던 핵심 데이터는 배경 소음 속에 묻히고 맙니다.

피그마를 활용해 화면을 다듬는다는 것은 화려한 그래픽 기술을 부리는 일이 아닙니다. "사용자가 이 카드에서 가장 먼저 읽어야 할 숫자는 무엇인가?", "굳이 상자로 가두지 않아도 여백만으로 구분할 수 있는 정보는 무엇인가?"를 구분해 시선의 우선순위를 정리하는 일입니다.

02편의 자동 배포 게이트, 03편의 오픈소스 스킬 조립, 그리고 이번 04편의 피그마 규격 기반 리디자인까지 거치며 이제 기능과 가독성을 모두 갖춘 나만의 실시간 정보 시스템이 완성되었습니다. 말로만 설명하기 답답했던 화면 수정 작업이 있다면, 이제 추상적인 형용사 대신 명확한 치수와 위계 규격을 AI에게 건네보시기 바랍니다.

AI 실전 04 · TAKEAWAY 피그마를 활용해 화면을 다듬는다는 것은 화려한 장식을 더하는 일이 아니라, 불필요한 상자를 걷어내고 사용자가 가장 먼저 읽어야 할 정보의 우선순위를 치수로 통제하는 일입니다.
