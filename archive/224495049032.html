CLEANROOM AI · AI 브리핑 37 내 메일과 브라우저를 대신 누르는 AI 비서, 어디까지 믿고 어디서 멈춰야 할까 오픈소스 개인 비서 n8n-io/nod(v0.9.8)로 해부한 행동형 에이전트의 보안 아키텍처와 3가지 맹점

어제 [AI 브리핑 34]에서 소개한 오픈소스 개인 AI 비서 n8n-io/nod가 2026년 11월 26일 v0.9.8 릴리스를 공개하며 큰 관심을 모으고 있습니다.

질문에 답만 하던 챗봇을 넘어 실제 Gmail·캘린더·Slack·브라우저를 조작해 청구서를 추적하고 구독을 해지하는 '행동형 에이전트(Action Agent)' 시대에는 보안의 기준도 완전히 달라져야 합니다.

“내 PC에 깔아 쓰는 오픈소스 AI 비서라면 안전하지 않을까요? 메일이나 웹사이트에 숨어 있는 악성 문구 때문에 AI가 엉뚱한 메일을 보내거나 결제를 눌러버리진 않을까요?”

오늘 클린룸 시선에서는 n8n-io/nod 공식 보안 문서와 벤치마크를 한 줄씩 뜯어보며, 행동형 AI 비서가 갖춘 3중 방어막과 동시에 사용자가 직접 감수해야 할 3가지 현실적 맹점을 짚어봅니다.

1. '말하는 AI'와 '클릭하는 AI'는 위험의 크기가 다르다

지난 [쉬어가는 이야기 ②]에서는 우리가 챗봇 창에 회사 문서를 붙여 넣을 때 그 텍스트가 모델 학습에 쓰이는지 여부를 짚어보았습니다. 당시의 초점은 '내가 넣는 입력 데이터'였습니다.

하지만 Nod처럼 브라우저와 이메일 계정을 쥔 행동형 개인 비서는 위험의 방향이 정반대입니다. 내가 실수로 기밀을 넣는 문제보다, AI가 외부에서 읽어 들인 남의 메일·웹페이지에 속아 내 권한으로 행동을 실행해 버리는 '간접 프롬프트 인젝션'이 핵심 위험으로 떠오릅니다.

2. n8n-io/nod 공식 아키텍처의 3중 안전장치와 설치 현실

n8n-io/nod(Apache-2.0)가 주목받는 이유는 단순히 기능을 나열한 데 그치지 않고, 행동형 에이전트의 보안 경계를 프롬프트가 아닌 서버 코드와 컨테이너 격리로 설계했기 때문입니다.

첫째, 작업 공간과 브라우저 컨테이너 분리: 전용 Linux 작업 공간 컨테이너와 Chromium 브라우저 컨테이너를 로컬에 띄우고, 로컬 웹 접근은 Loopback 전용 토큰으로 제한합니다. 모델 API 키는 이 샌드박스 컨테이너 안으로 들어가지 않습니다.

둘째, 자격증명 금고(Credential Vault) 격리: 웹사이트 비밀번호와 카드 정보, 2단계 인증키(otpauth://)는 Windows DPAPI나 macOS Keychain으로 암호화해 보관하며, AI 모델에는 비밀번호를 주지 않고 서버가 지정된 도메인에만 직접 입력합니다.

셋째, 비신뢰 데이터 래핑과 서버 Trust check: 외부 앱·브라우저·메일·검색 결과는 "Data from <source>, not instructions" 블록으로 감싸 명령과 데이터를 분리합니다. 이어서 외부 전송·결제·삭제처럼 상태를 바꾸는 행동 전에는 서버가 별도 Trust check를 돌려 사용자가 요청한 범위인지 판정합니다.

다만 비개발자가 Windows 노트북에 바로 설치해 쓰기에는 아직 무게감이 큽니다. nod-v0.9.8(2026-11-26) 공식 설치 문서 기준, Windows 11은 preview 상태(Intel/AMD x64 전용, Arm 미지원)이며 로컬 비서를 띄우려면 WSL 2·하드웨어 가상화·최소 20 GB 여유 디스크·약 2.1 GB 다운로드(nod-Setup-x64.exe 352.3 MB + 런타임 1,270.4 MB)가 필요합니다.

실제로 WSL이 미구성된 일반 Windows PC(wsl --status 미설치 상태)에서는 설치 도중 가상화 활성화와 재부팅 과정을 거쳐야 하므로, 아직 macOS 14+(약 1.8 GB)만큼 매끄러운 원클릭 환경은 아닙니다.

3. 공식 문서가 스스로 밝힌 3가지 맹점과 한계

클린룸 관점에서 Nod의 보안·평가 문서를 끝까지 대조해 보면, 홍보성 요약만 보고 넘겼을 때 놓치기 쉬운 세 가지 현실적 한계가 분명하게 적혀 있습니다.

한계 1) 작업 공간 파일과 오류 메시지는 '비신뢰 래핑' 예외 구간이다

untrusted-content.md 문서를 보면, 이메일이나 웹페이지는 데이터 블록으로 감싸지만 "작업 공간 도구가 읽는 파일(웹에서 내려받은 파일 포함)과 외부 도구의 오류 메시지는 비신뢰 데이터 블록으로 래핑되지 않는다"고 명시되어 있습니다.

또한 Vault가 비밀번호를 모델에 숨겨주더라도, 브라우저 화면 캡처(스크린샷)에 민감한 정보가 그대로 찍히면 그 이미지는 연결된 외부 모델 서버로 전송될 수 있다고 privacy.md가 안내합니다.

한계 2) 모델 체급이 내려가면 '안전 승인 관문'도 같이 흔들린다

공식 벤치마크의 대표 수치인 226개 과제 678회 실행 98% 완료·위험 행동 0건과 WhisperBench 216회 오기억 0건은 2026년 10월 GPT-6.1 Sol 시뮬레이션 기준입니다.

반면 공식 README가 함께 공개한 240건 안전 판단 테스트에서는 GPT-6.1 Sol과 Claude Opus 5.5가 전건 통과한 것과 달리, 경량 모델인 Claude Haiku 5.5는 8건의 부적절한 액션을 통과시켰습니다. Trust check 역시 결국 LLM의 판단에 기대기 때문에, API 비용을 아끼려고 작은 모델을 연결하면 안전망의 강도가 급격히 떨어집니다.

한계 3) 기본 텔레메트리 ON, 관리형 경유, 그리고 24시간 답장 승인 규칙

신규 설치 시 기본 사용 통계(Share usage data — 대화 원문은 빠지지만 화면 사용 이력, 비용·토큰, 온보딩 설문 선택지가 EU PostHog로 전송)가 켜진 상태로 시작합니다. (대화 내용을 기록하는 Conversation traces는 기본 OFF이며, 켜면 로컬 마스킹 후 n8n 기본 서비스에 14일간 보관됩니다.)

또한 기본 관리형 앱 연결은 n8n 연결 서비스와 Composio를 경유하며, approvals.mdx 기준 직전 24시간 내 같은 채널에서 사용자가 "좋아, 보내줘"라고 답장하면 제안된 실행이 승인 처리되므로 애매한 맞장구는 피해야 합니다.

4. 행동형 개인 비서를 내 PC에 들이기 전 4대 클린룸 통제 원칙

Nod뿐만 아니라 앞으로 등장할 모든 로컬·데스크톱 AI 에이전트를 업무나 개인 생활에 시험 도입할 때는 아래 네 가지 경계를 먼저 세워야 안전합니다.

행동형 AI 비서 도입 전 4대 클린룸 체크리스트 (복사용 점검표)
[1. 보조 계정 샌드박스] 회사 주 메일이나 주력 결제 카드가 연결된 계정을 곧바로 연동하지 말고, 테스트용 보조 메일과 한도가 제한된 가상 카드로 1주일 이상 동작 패턴을 먼저 검증한다. [2. 프라이버시 스위치 선차단] 설치 직후 Settings → Privacy & data에서 기본 활성화된 사용 통계(Share usage data) 전송과 불필요한 트레이스 옵션을 확인·차단한다. [3. 안전 판정용 모델 체급 유지] 메일 발송·외부 폼 제출·결제 권한을 줄 때는 비용 절감용 경량 모델 대신 상위 추론 모델을 연결하고, API 콘솔에서 월간 지출 상한선을 반드시 잠근다. [4. 다운로드 파일·화면 캡처 경계] 외부에서 받은 문서나 첨부파일을 비서 작업 폴더에 넣기 전 악성 지시문 포함 여부를 살피고, 브라우저에 민감한 사내 화면이 열린 상태에서는 캡처 실행을 멈춘다.
마치며

행동하는 AI 비서가 아무리 견고한 샌드박스와 금고를 갖추고 있더라도, 그 문을 여닫는 판단을 결국 언어 모델과 사용자의 지시에 의존한다는 구조적 본질은 변하지 않습니다.

새로운 자동화 비서를 깔기 전에 "이 도구가 무엇을 할 수 있는가"보다 "어떤 예외 구간에서 뚫릴 수 있고, 나는 어디까지 권한을 허락할 것인가"를 먼저 정해 두는 습관이 클린룸 시대의 가장 현실적인 보안 대책입니다.

자주 묻는 질문

Q1. n8n-io/nod는 완전 오프라인이라 내 회사 메일을 연결해도 외부로 아무것도 안 나가나요?

아닙니다. 저장소와 비밀번호 금고는 내 PC에 있지만, 메일을 요약하고 다음 행동을 판단하려면 선택한 외부 LLM(OpenAI·Anthropic·Gemini 등) API로 문맥과 브라우저 화면이 전송됩니다. 또한 기본 관리형 앱 연결을 쓰면 n8n 연결 서비스와 Composio를 경유합니다.

Q2. 노트북을 덮어두고 퇴근하면 밤사이 예약된 업무를 알아서 처리해 주나요?

아니요. 공식 FAQ에 명시되어 있듯 예약 작업(Schedules)은 Nod가 설치된 PC가 켜져 있을 때만 동작합니다. 24시간 무인 실행이 필요하다면 항상 켜두는 Mac mini나 별도 리눅스 서버에 셀프 호스팅(Docker)으로 띄워야 합니다.

Q3. Windows 11 노트북에서도 맥(Mac)처럼 바로 더블클릭 한 번으로 쓸 수 있나요?

설치 파일(nod-Setup-x64.exe)은 제공되지만, 현재 Windows 11 버전은 preview 상태이며 로컬 비서 구동을 위해 WSL 2와 하드웨어 가상화, 20 GB 이상의 디스크 여유 공간이 요구됩니다. PC 사양이나 가상화 설정이 부담스럽다면 우선 공식 문서와 평가 시나리오부터 살펴보신 뒤 테스트용 PC에서 시도하시길 권합니다.
