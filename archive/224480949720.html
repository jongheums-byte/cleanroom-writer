예전에 발행한 [AI 브리핑.03 — 질문에 답하는 AI에서, 직접 일을 끝내는 AI로: 에이전트(Agent)의 등장] 편에서, 단순한 챗봇과 실제 업무를 완수하는 '에이전트'가 어떻게 다른지 살펴본 적이 있습니다.

그동안 이 블로그의 [AI 실전 01 ~ 12] 시리즈에서 웹페이지를 만들고, 구글 드라이브 문서를 스캔하고, 오픈소스 SEO 엔진을 돌려본 작업실이 바로 구글의 에이전트 플랫폼인 구글 안티그래비티(Google Antigravity)입니다.

아직 주변에서 안티그래비티라는 이름을 생소해하는 분들이 많지만, 실제로 써보면 단순한 코딩 도구를 넘어 왜 이 환경이 '에이전트 지휘소'로 불리는지 분명한 이유가 있습니다. 최근 대규모 업데이트 내용을 포함해, 다른 도구에서는 보기 힘든 안티그래비티만의 핵심 특장점 4가지를 정리해 봅니다.

1. Orchestrator (Argon) 모드: '설계자'와 '실행자'의 2단계 분리

이번 업데이트에서 가장 강력한 변화는 모델 선택창에 새로 추가된 Orchestrator (Argon) 모드입니다.

보통 AI에게 복잡한 작업을 시키면, 비싸고 무거운 모델이 단순 파일 수정이나 반복 명령어 실행까지 혼자 다 처리하느라 속도도 느려지고 사용량 한도(쿼터)도 금세 소진됩니다.

안티그래비티의 Orchestrator (Argon) 모드는 한 번의 작업을 두 단계(2-Phase)로 엄격하게 나눕니다.

설계 단계 (Plan Mode): 가장 치밀한 상위 모델(Argon)이 먼저 읽기 전용(Read-only) 상태로 파일과 구조를 조사해, 수정이 필요한 위치·검증 방법·예외 기준("Re-plan if")이 담긴 완벽한 작업 계획서를 작성합니다.

실행 단계 (Execute Mode): 계획이 확정되면 빠르고 가벼운 실행 모델에게 바통을 넘겨 실제 파일 생성과 명령어 실행을 빠르게 처리합니다. 실행 중 예상치 못한 문제가 생기면 임의로 추측하지 않고 다시 설계 모델에게 검토([plan review])를 요청합니다.

집을 지을 때 총괄 건축가가 먼저 치밀한 설계 도면을 그리면, 현장 시공팀이 그 도면대로 빠르게 공사를 진행하고, 현장에서 도면과 다른 변수가 생기면 임의로 고치지 않고 다시 건축가에게 확인을 받는 분업 구조를 그대로 옮겨놓은 셈입니다. 덕분에 고급 모델의 사용량은 아끼면서도 결과물의 완성도는 높게 유지할 수 있습니다.

2. 구글 Gemini 4부터 Claude 5.5까지 아우르는 멀티 모델 지휘소

두 번째 특장점은 특정 모델 하나에 갇히지 않는 개방성입니다.

안티그래비티의 모델 선택창을 열어보면 구글의 차세대 라인업인 Gemini 4 Argon과 Gemini 4 Hydrogen, 빠른 응답용 Gemini 3.8 Flash뿐 아니라, 앤트로픽의 최신 Claude Opus 5.5와 Claude Sonnet 5.5, 오픈소스 계열인 GPT-OSS 120B까지 한자리에서 골라 쓸 수 있습니다.

방대한 문서 맥락 파악과 멀티모달 분석이 필요할 때는 Gemini 4 계열

정교한 문장 구조 다듬기나 코드 리팩토링이 필요할 때는 Claude 5.5 계열

설계는 무겁게, 실행은 가볍게 가져가고 싶을 때는 Orchestrator (Argon)

처럼 하나의 대화 흐름 안에서도 작업 성격에 맞춰 모델을 즉시 교체할 수 있고, 하단의 View Usage 버튼으로 잔여 사용량을 실시간으로 확인하며 자원을 배분할 수 있습니다.

3. 메인 작업대를 어지럽히지 않는 '전담 서브에이전트(Subagents)' 분업

지난 [AI 브리핑.21(컨텍스트 엔지니어링)]에서 살펴보았듯, 한 대화창 안에서 자료 조사와 웹 탐색, 파일 수정을 한꺼번에 처리하면 맥락 창(Context Window)이 금세 어지러워집니다.

안티그래비티는 이를 막기 위해 역할이 분리된 전담 서브에이전트(Subagents)를 백그라운드로 파견합니다.

research 서브에이전트: 방대한 파일 탐색이나 조사가 필요할 때 별도의 읽기 전용 공간에서 조사를 마친 뒤 핵심 결론만 본부(메인 대화창)로 보고합니다.

browser 서브에이전트: 내장된 전용 브라우저를 직접 띄워 내가 만든 웹페이지를 클릭해 보고 화면 상태를 점검합니다. 이때 실제로 방문한 도메인과 화면 캡처를 시스템이 별도로 검증(BROWSER_HOST_FACTS)해 보고서의 신뢰도를 보장합니다.

image-generator 및 Swarm(/teamwork): 이미지 생성 전담 에이전트나 여러 에이전트가 공유 보드에서 동시에 협업하는 스웜 모드까지 지원합니다.

즉, 메인 에이전트는 항상 깔끔하게 정돈된 책상을 유지한 채 전담 비서들의 요약 보고만 받아 최종 결정을 내릴 수 있습니다.

4. 내 업무 기준을 시스템에 심는 3중 서랍 구조 (Rules · Skills · Plugins)

마지막으로 안티그래비티가 실무자에게 강력한 이유는 '내 기준'을 시스템에 고정해 둘 수 있는 3중 서랍 구조와 백그라운드 자동화 때문입니다.

상시 원칙 (User Rules / GEMINI.md): 어떤 대화를 열든 AI가 절대 어기면 안 되는 기본 수칙을 박아둡니다. (예: "블로그 HTML 파일을 만들기 전에는 반드시 검수 요약과 마크다운 초안을 먼저 보여주고 '승인'을 받아라.")

업무 매뉴얼 (Skills / SKILL.md): 특정 작업을 할 때만 꺼내 읽는 업무 인수인계서입니다. 금지어 목록이나 문체 규칙, SEO 진단 절차를 넣어두면 매번 프롬프트를 길게 칠 필요가 없습니다.

외부 손발 (Plugins & MCP): 구글 드라이브, 피그마, 크롬 개발자 도구 등을 마켓플레이스에서 연결해 두면, 복사·붙여넣기 없이 AI가 내 문서함과 도면에 직접 접근합니다.

기다리지 않는 백그라운드 작업 (Reactive Wakeup & /schedule): 무거운 프로그램 설치나 정기 작업을 백그라운드에 띄워두면, 작업이 끝나는 순간 시스템이 알아서 에이전트를 깨워 다음 단계를 이어갑니다.

맺음말 (다음 편 예고)

결국 구글 안티그래비티의 진짜 가치는 "대답을 잘하는 AI"가 아니라, 설계와 시공을 분리(Orchestrator)하고, 전담 비서를 파견(Subagents)하며, 내 업무 매뉴얼(Rules & Skills) 안에서 움직이는 '나만의 자동화 작업실'이라는 데 있습니다.

이어지는 2회차 실전편([AI 실전 13])에서는 안티그래비티를 처음 켠 분이 10분 만에 따라 할 수 있는 Rules · Skills · Plugins 3단 실전 세팅법을 직접 화면과 함께 짚어드리겠습니다.
