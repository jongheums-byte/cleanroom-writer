CLEANROOM WRITER AI 실전 03 매번 검색하는 생활 정보를 한 화면에 — 오픈소스 스킬(k-skill)을 조립해 언제든 갈아끼우는 나만의 조회 사이트 만들기 항공권·최저가 주유소·공영주차장·로또 조회까지, 깃허브의 AI 스킬을 웹 모듈로 이식하고 원할 때마다 기능을 업데이트하는 설계법 CLEANROOM AI TECH · MODULAR WEB ARCHITECTURE

지난 [AI 실전 02] 편에서는 마우스 드래그 방식의 웹 빌더 대신 코드로 정적 아카이브를 짓고, 넷리파이(Netlify)를 통해 배포하는 기본 공정을 다루었습니다.

하지만 지난번에 만든 사이트는 내가 작성한 글 목록과 링크를 깔끔하게 진열해 두는 '정적(Static) 쇼룸'에 가까웠습니다. 웹페이지의 구조를 한 번 잡아두면 안정적으로 굴러가지만, 외부에서 시시각각 변하는 생활 정보를 실시간으로 끌어와 보여주는 역할은 하지 못합니다.

이번 3편에서는 한 단계 더 나아가, 깃허브(GitHub)에 공개된 한국형 오픈소스 스킬 모음집인 'k-skill(NomaDamas/k-skill)'을 활용해 실시간 생활 정보 조회 사이트를 구축해 보겠습니다. 특히 단순히 네 가지 기능을 한 번 만들어 배포하는 데 그치지 않고, 내가 원할 때마다 134개의 스킬 중 필요한 정보 카드로 언제든 갈아끼울 수 있는 '모듈형(Modular) 구조'로 설계하는 것이 이번 실습의 핵심입니다.

왜 매번 4개의 앱과 포털을 따로 열어야 할까?

주말 나들이나 휴가 계획을 세울 때, 혹은 일상적인 이동을 준비할 때 우리가 스마트폰이나 PC에서 거치는 동선을 떠올려 봅시다.

항공권 가격 추이를 보려면 여행 비교 사이트를 열고, 출발 전 주유를 위해 오피넷이나 내비게이션 앱을 뒤적입니다. 목적지 주변의 저렴한 공영주차장을 찾으려 지도 앱을 다시 검색하고, 주말 저녁에는 포털 사이트에 '로또 당첨 번호'를 입력해 결과를 확인합니다. 필요한 정보는 각각 한두 줄뿐인데, 매번 서로 다른 앱을 열고 광고와 복잡한 메뉴를 통과해야 합니다.

만약 내가 자주 확인하는 이 네 가지 정보만 한 화면에 모아두고, 접속하는 즉시 핵심 수치만 확인할 수 있다면 어떨까요? 나아가 평일에는 '출근길 지하철·날씨' 화면으로 쓰다가, 주말에는 '주유소·공영주차장·항공권' 화면으로 부품을 갈아끼울 수 있다면 활용도는 훨씬 높아질 것입니다.

재료 탐색: 깃허브 오픈소스 'k-skill'에 담긴 134개의 연장

처음부터 항공권 검색 엔진이나 주유소 좌표 변환 공식, 동행복권 데이터 수집기를 직접 코딩할 필요는 없습니다. 깃허브에 공개된 오픈소스 저장소인 NomaDamas/k-skill에는 이미 한국인의 실생활에 맞춘 134개의 자동화 도구(스킬)가 정리되어 있기 때문입니다.

이 저장소에서 오늘 우리가 꺼내 쓸 네 가지 핵심 도구는 다음과 같습니다.

1. 항공권 가격 조회 (flight-ticket-search): 구글 플라이트(Google Flights)의 공개 검색 표면을 활용해 노선별 최저가·평균가를 비교하고 검색 직행 링크를 생성하는 스킬입니다. 2. 근처 가장 싼 주유소 찾기 (cheap-gas-nearby): 현재 위치의 위도·경도를 오피넷(Opinet) 전용 좌표계(KATEC)로 변환해 반경 내 최저가 주유소와 셀프·세차 여부를 찾아주는 스킬입니다. 3. 근처 공영주차장 찾기 (parking-lot-search): 공공데이터포털의 전국주차장정보 표준데이터를 기반으로 주변 공영주차장의 위치, 거리, 기본요금, 운영시간을 조회하는 스킬입니다. 4. 로또 당첨 번호 조회 (lotto-results): 동행복권의 공식 회차별 추첨 결과 데이터를 호출해 당첨 번호와 1등 당첨금, 당첨 게임 수를 정리해 주는 스킬입니다.

문제는 이 스킬들이 원래 클로드 코드(Claude Code)나 안티그래비티(Antigravity) 같은 'AI 에이전트 환경' 안에서 명령어로 실행하도록 만들어진 파이썬(Python)·자바스크립트 부품이라는 점입니다. 이를 일반 웹 브라우저에서 누구나 클릭만으로 쓸 수 있게 만들려면, 스킬 내부의 조회 원리만 뽑아내어 웹 화면으로 옮겨 심는 '역설계(Reverse-engineering, 완성된 프로그램의 내부 구조를 분석해 핵심 동작 원리를 추출하는 작업)' 과정이 필요합니다.

핵심 설계: 전체를 다시 짜지 않고 '부품'만 교체하는 모듈형 표준화

AI에게 "항공권, 주유소, 주차장, 로또를 조회하는 사이트를 만들어 줘"라고 단순하게 지시하면, 네 가지 기능이 하나의 코드 파일 안에 길게 뒤엉킨 일체형 웹페이지가 만들어집니다. 당장은 작동하더라도 다음 주에 '로또 조회' 자리에 '식약처 의약품 조회'나 '실시간 지하철 도착 정보'를 넣고 싶어지면 화면 전체를 다시 짜야 합니다.

제조 현장의 엔지니어링에서는 이런 비효율을 막기 위해 설비를 설계할 때부터 '모듈형 규격화(Modular Qualification)' 원칙을 적용합니다. 생산 라인의 본체(Frame)와 개별 작업 장치(Module)가 연결되는 입출력 규격(Interface)을 표준화해 두는 것입니다. 이렇게 해두면 공정 목적이 바뀔 때 라인 전체를 철거할 필요 없이, 규격에 맞는 새 모듈만 슬롯(Slot)에 끼워 넣어 즉시 가동할 수 있습니다.

우리가 만들 개인 조회 사이트도 똑같은 원리로 짓습니다.

• 화면 본체 (index.html): 데이터를 보여주는 4개의 빈 칸(SLOT #01 ~ SLOT #04)과 상단 프리셋 버튼만 고정해 둡니다. • 스킬 등록부 (SKILL_REGISTRY): 각 스킬이 데이터를 어디서 가져오는지(buildEndpoint)와 화면에 어떻게 그릴지(render)를 동일한 규격의 블록으로 정의해 둡니다.

이 구조를 먼저 세워두면, 나중에 k-skill의 134개 스킬 중 어떤 것이든 새로운 블록 하나만 등록부에 추가해 드롭다운 메뉴에서 즉시 갈아끼울 수 있습니다.

[실습] 오픈소스 스킬을 내 웹 사이트로 이식하는 3단계 공정

1단계: AI에게 오픈소스 스킬의 '조회 공식'만 추출하게 하기

먼저 AI 에이전트에게 NomaDamas/k-skill 저장소의 네 가지 스킬 폴더(flight-ticket-search, cheap-gas-nearby, parking-lot-search, lotto-results)를 읽게 한 뒤, 웹 이식을 위한 요구사항을 전달합니다.

실무 지시 프롬프트 예시: "NomaDamas/k-skill 저장소에서 항공권(flight-ticket-search), 최저가 주유소(cheap-gas-nearby), 공영주차장(parking-lot-search), 로또 결과(lotto-results) 스킬의 소스 코드를 분석해 줘. 에이전트 없이 일반 웹 브라우저에서 바로 조회할 수 있도록 각 스킬의 호출 주소(Endpoint)와 좌표 변환·데이터 파싱 로직만 추출해서 4개의 슬롯(Slot) 카드로 구성해 줘. 특히 내가 나중에 다른 스킬로 언제든 업데이트할 수 있도록, 모든 스킬을 SKILL_REGISTRY 객체 안에 독립된 모듈 규격으로 분리해서 작성해 줘."

이 지시를 받은 AI는 각 스킬 폴더의 파이썬 스크립트와 자바스크립트 파서(parse.js)를 분석해 핵심 부품만 발라냅니다. 예를 들어 주유소 스킬에서는 일반 위도·경도(WGS84)를 오피넷 전용 좌표(KATEC)로 바꾸는 수학 공식을 그대로 웹 스크립트로 옮겨오고, 주차장 스킬에서는 "실시간 만차 여부는 공공데이터 표준 규격에 없으므로 단정하지 말고 지도 링크로 교차 확인하게 하라"는 SKILL.md의 검증 지침까지 화면 하단 안내문으로 함께 반영합니다.

2단계: 브라우저 보안 차단(CORS)을 우회하는 프록시 통로 열기

02편에서 다루었던 정적 웹사이트와 이번 실시간 조회 사이트의 가장 큰 기술적 차이는 '외부 서버와의 통신'에 있습니다.

웹 브라우저는 보안상의 이유로, 내 사이트(my-site.netlify.app)가 주소가 다른 외부 서버(예: 동행복권 서버나 k-skill 공공데이터 프록시 서버)의 데이터를 직접 호출하면 이를 차단합니다. 이를 CORS(Cross-Origin Resource Sharing, 교차 출처 리소스 공유 제한 — 웹 브라우저가 허가되지 않은 다른 도메인의 데이터를 직접 읽지 못하게 막는 보안 규칙)라고 부릅니다.

별도의 백엔드 서버를 직접 구축하지 않고도 이 장벽을 넘는 가장 깔끔한 방법은, 넷리파이 설정 파일(netlify.toml)에 '리버스 프록시(Reverse Proxy, 브라우저의 요청을 같은 사이트 주소로 받은 뒤 뒤단에서 외부 서버로 대신 전달해 주는 중계 규칙)' 몇 줄을 적어두는 것입니다.

# netlify.toml — 브라우저 보안 차단(CORS) 우회 및 외부 데이터 중계 규칙 [[redirects]] from &#x3D; "/api/k-skill/*" to &#x3D; "https://k-skill-proxy.nomadamas.org/v1/:splat" status &#x3D; 200 force &#x3D; true [[redirects]] from &#x3D; "/api/lotto/*" to &#x3D; "https://www.dhlottery.co.kr/lt645/:splat" status &#x3D; 200 force &#x3D; true

이렇게 설정 파일을 함께 넣어두면, 내 웹페이지는 /api/lotto/...나 /api/k-skill/...처럼 자기 자신의 내부 주소를 부르는 것처럼 작동하고, 실제 외부 데이터 통신은 넷리파이 중계기가 대신 처리해 주므로 인증키 노출이나 브라우저 차단 없이 실시간 응답을 받아올 수 있습니다.

3단계: 완성된 4대 생활 정보 슬롯과 '스킬 모듈 교체' 확인

구축이 완료된 화면을 열면, 4개의 규격화된 슬롯 카드에 대중적인 생활 정보 4종이 일목요연하게 정리되어 나타납니다.

• SLOT #01 (항공권 최저가 비교): 인천→도쿄, 인천→오사카, 김포→제주 등 주요 노선을 선택하면 노선 평균가 대비 절감 폭과 항공사별 최저가 후보, 구글 플라이트 검색 직행 링크가 표시됩니다. • SLOT #02 (근처 가장 싼 주유소): 강남역, 서울역, 여의도, 성수동, 판교 등 권역을 고르면 변환된 KATEC 좌표를 기준으로 반경 내 최저가 주유소 순위와 셀프·세차·품질인증 여부가 정렬됩니다. • SLOT #03 (근처 공영주차장): 광화문, 강남역, 성수동, 홍대입구 등 목적지를 선택하면 가까운 공영주차장의 거리, 5분·1시간 기준 요금, 운영시간과 카카오맵 바로가기 버튼이 제공됩니다. • SLOT #04 (로또 당첨 번호 조회): 회차 번호(예: 1220회)를 입력하면 동행복권 공식 데이터를 실시간으로 불러와 당첨 번호 6개와 보너스 번호, 1등 당첨금 규모와 자동·수동 비율을 즉시 보여줍니다.

여기서 가장 중요한 기능은 각 카드 우측 상단에 배치된 [🔄 스킬 모듈 교체] 드롭다운 메뉴와 상단의 프리셋 전환 버튼입니다.

평소에는 항공권·주유소·주차장·로또 4종으로 띄워두고 쓰다가, 출근길에는 드롭다운을 열어 1번 슬롯을 '기상청 초단기실황 날씨(korea-weather)'로, 2번 슬롯을 '서울 지하철 실시간 도착(seoul-subway)'으로, 혹은 필요할 때 '식약처 의약품 안전 정보 조회(mfds-drug-safety)'로 즉시 갈아끼울 수 있습니다.

새로운 스킬로 내 사이트를 업데이트하는 법

나중에 NomaDamas/k-skill 저장소에서 또 다른 흥미로운 스킬(예: KTX 잔여석 확인, 영화 박스오피스, 도서관 신착 도서 검색 등)을 발견했을 때도 사이트를 새로 만들 필요가 없습니다.

AI에게 "기존 app.js의 SKILL_REGISTRY 규격에 맞춰 k-skill의 OO 스킬 블록 하나만 밑에 추가해 줘"라고 한 줄만 지시하면 됩니다. 화면 레이아웃이나 다른 세 개의 카드 코드는 건드리지 않은 채, 드롭다운 목록에 새로운 정보 카드가 아홉 번째 부품으로 조용히 추가됩니다.
